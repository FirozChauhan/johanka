Johanka — Project Documentation

A minimal, self-hosted video streaming service built with Next.js. This guide walks a complete beginner through every file, concept, and data flow in the project — written for someone who is new to Next.js.

Next.js 15.5React 19TypeScript 5.8Tailwind CSS 4Node.js 20+DockerPostgreSQLFirebaseStreamTape

01 What is Johanka?

Johanka is a personal, self-hosted "Netflix-style" video streaming app. The clever part: it does not store any video files on its own server. Instead it uses StreamTape (a free file-hosting service) as the actual storage and streaming backend, and Johanka just acts as the clean front-end that lists, uploads, and plays those videos.

Think of it like a pretty remote control for your StreamTape account. When you open the home page, Johanka asks StreamTape "what videos do I have?", shows them in a nice grid, and when you click one, it embeds StreamTape's built-in video player.

The big picture (one sentence)

browser → Next.js server → StreamTape (FTP for uploads, REST API for listing, iframe for playback).

What it does (features)

  • Live library — every file in your StreamTape account appears automatically. You can also limit it to one folder.
  • Upload — drag & drop a video (mp4, webm, mkv, mov…). It streams through Johanka's server and lands in your StreamTape account over FTP.
  • Auto thumbnails — StreamTape generates a poster image after it processes each video. No ffmpeg needed.
  • Streaming — playback uses StreamTape's embeddable iframe player (free, no transcoding).
  • Search & Continue Watching — search by title (URL-based) and a "continue watching" row driven by localStorage.
  • Optional Google sign-in — via Firebase; guests can browse without an account.
  • Locked /settings page — an operator dashboard protected by an admin key, where you configure StreamTape credentials and an optional PostgreSQL database.
Why StreamTape? Free storage + streaming + auto-generated thumbnails. Johanka intentionally keeps no media files on disk — the server only ever proxies bytes through during an upload, then deletes the temp file. This makes it cheap to host (even on a 512MB free tier).

03 Next.js for Beginners

Since you're new to Next.js, here's a quick crash course on the concepts this project actually uses. This will make every other section make sense.

3.1 The App Router

Next.js has two ways of routing. This project uses the newer App Router, which lives in the app/ folder. The rule is beautifully simple: folders become URL paths.

  • app/page.tsx → / (home page)
  • app/upload/page.tsx → /upload
  • app/settings/page.tsx → /settings
  • app/watch/[id]/page.tsx → /watch/ANYTHING (a dynamic route; the [id] part is a variable)

3.2 Special files inside a folder

Inside each route folder, Next.js looks for specially-named files:

FilePurpose
page.tsxThe page itself — what the user sees at that URL.
loading.tsxShown automatically while the page is loading (a "skeleton").
not-found.tsxThe 404 page for the whole app.
route.tsInside app/api/... folders, this file IS an HTTP endpoint instead of a page.
layout.tsxA wrapper shared by all pages. The root layout holds the <html> and <body>.
icon.svgThe favicon.

3.3 Route groups — the weird (home) folder

You'll see app/(home)/page.tsx. The parentheses make it a route group. A folder in parentheses is invisible to the URL — (home) doesn't appear in the path. It exists purely for organisation: you can give a group its own loading.tsx or layout without affecting the URL. So (home)/page.tsx is still served at /.

3.4 "use client" — the most important line

At the top of many files you'll see "use client";. This is Next.js's way of splitting the app into two worlds:

  • Server Components (default): render on the server, ship HTML to the browser. They cannot use hooks like useState or useEffect, and can't listen to clicks.
  • Client Components (files starting with "use client"): render in the browser. They CAN use state, effects, event handlers, browser APIs like localStorage.

Files that need interactivity (search box, upload form, the video grid that fetches data on load) therefore start with "use client". Files that are pure/static (like layout.tsx exporting metadata) stay as server components.

Pattern in this project: most pages are client components because they fetch the library from the API in a useEffect and update state. The root layout.tsx is a server component (it just sets up fonts, metadata, and the shell).

3.5 API Routes (Route Handlers)

Inside app/api/, each route.ts file exports functions named after HTTP verbs:

export async function GET(req) { ... }   // runs when someone sends GET to this URL
export async function POST(req) { ... }  // runs on POST
export async function DELETE(req, { params }) { ... }

So app/api/upload/route.ts exporting POST means "a POST request to /api/upload runs this code". You return a NextResponse.json(...) and Next turns it into an HTTP response.

3.6 Two config flags you'll see in routes

LineMeaning
export const runtime = "nodejs";Run this route in the full Node.js runtime (not the limited "edge" runtime). Needed for things like fs, FTP, native modules.
export const dynamic = "force-dynamic";Never cache this response — re-run it every request. Used for endpoints that read live data or env vars at runtime.

3.7 Path alias @/

In tsconfig.json there's "paths": { "@/*": ["./*"] }. This means @/lib/types is short for the file at ./lib/types.ts (relative to the project root). You'll see imports like import { Video } from "@/lib/types" everywhere — it's just a cleaner way to write relative paths.

You now know enough Next.js to read this whole project! The rest is just regular React + TypeScript + Tailwind, plus some Node.js server code for talking to StreamTape/PostgreSQL.

05 Architecture & Data Flow

Johanka is a thin Next.js app sitting between the browser and StreamTape. The server never stores video files; it only (a) lists what's in your StreamTape account, (b) forwards uploads to StreamTape over FTP, and (c) embeds StreamTape's player. Settings/users optionally live in PostgreSQL.

5.1 The three-tier flow

BrowserReact client components
UI, search, upload form
→
Next.js serverAPI routes in app/api
resolves creds from env+DB
→
StreamTapefree storage + player
REST API + FTP

The browser never knows your StreamTape credentials. Every API route resolves them server-side (env vars win over the DB). This keeps secrets off the client and makes the library identical for every visitor.

5.2 Where state lives

WhatWhereWhy
Video library (the list of videos)StreamTape itself (read live via /api/streamtape/files)No DB needed; mirrors the account exactly. localStorage is a fallback only.
Watch history ("continue watching")Browser localStorage (johanka:history)Per-device, no account required.
Operator settings (StreamTape creds, folder id, DSN)PostgreSQL settings table (optional)Survives across browsers/incognito. Env vars always override.
Admin keySHA-256 hash in PostgreSQL OR JOHANKA_ADMIN_KEY env varNever stored in plaintext; env var always wins.
Signed-in users (Google)PostgreSQL users table (optional)Best-effort; a healthy session works even if the DB is down.
SessionHTTP-only cookie johanka_session (Firebase-verified)Secure, survives reloads, 14-day expiry.
Guest identityHTTP-only cookie johanka_guest + localStorage flagNo DB row; 30-day cookie.
Admin key (this tab only)In-memory JS variable (lib/admin-auth.ts)Deliberately not persisted — reload re-prompts for safety.

5.3 Caching strategy

To avoid hammering the StreamTape API on every page load, /api/streamtape/files keeps two in-memory caches:

  • Listing cache — the full library is cached for 30 seconds per credentials+folder key.
  • Splash cache — thumbnail URLs (from /file/getsplash) are cached for 10 minutes on success or 2 minutes on failure (so a still-processing video re-checks sooner).
Note: these caches are in-process (module-level Maps), so they reset on every server restart. That's fine — they're just a debounce, not a source of truth.

07 app/layout.tsx — The Root Layout

This is the outermost wrapper for every page. It's a server component (no "use client") because it only sets up fonts, metadata, and the static shell.

app/layout.tsxServer Component

What it does, line by line:

  • Fonts — loads Google Fonts via next/font/google: Inter (the sans body font, exposed as --font-sans) and Aref_Ruqaa_Ink (an Arabic calligraphy font used for the footer signature, exposed as --font-aref-ruqaa). next/font self-hosts fonts so there's no external request.
  • Metadata — exports a Metadata object: default title "Johanka — minimal self-hosted video streaming", a title template (%s · Johanka), description, OpenGraph tags, and the favicon. Individual pages can override the title.
  • Viewport — exports a Viewport object setting themeColor and colorScheme: dark.
  • The shell — the returned JSX wraps everything in <AuthProvider> (the auth context), renders <TopBar />, a <Sidebar />, then <AuthGate>{children}</AuthGate> (which blocks the app until you sign in / continue as guest), and a <FooterBar />.
  • FooterBar — a sticky footer showing "Johanka v<version>" on the left and the maker's name in Aref Ruqaa Ink (RTL) on the right.
Why <AuthProvider> here? Putting it in the root layout means the auth state is available to every page and the <AuthGate> can read it. The provider is a client component itself, but it can wrap server-rendered children just fine.

08 app/(home)/page.tsx — The Library (Home Page)

This is the main page at /. It's a client component because it fetches the video list and updates state.

app/(home)/page.tsxClient Component

Key logic inside HomeContent():

  • Search via URL — reads ?q= from the URL with useSearchParams(). The search box (in Nav.tsx) writes to this param, so search is "shareable" and survives reloads. Wrapped in <Suspense> because useSearchParams requires it.
  • Load the library — in a useEffect, calls fetchRemoteVideos() (which hits /api/streamtape/files). If that returns results, use them; otherwise fall back to getStoredVideos() (localStorage). Sets loading=false when done.
  • Filtering — if there's a ?q= query, filter videos by title (case-insensitive). The hero is hidden while searching so results read as search results.
  • Featured hero — the newest video (by created_at) becomes the big <HeroVideo> banner at the top.
  • Continue watching — renders <ContinueWatching> (only when not searching) above the grid.
  • The grid — <VideoGrid videos={filtered} /> shows the matching videos as cards.
  • Empty state — a friendly "Your library is empty" card with an upload button when there are no videos, or "No videos match" when searching finds nothing.
  • Loading skeleton — HomeLoading() shows shimmer placeholders for the hero + 8 cards while loading.
app/(home)/loading.tsxAuto Skeleton

A skeleton screen (shimmer blocks) that Next shows automatically while the route segment is loading. Same visual idea as HomeLoading but triggered by the framework's loading state, not by component state.

09 app/upload/page.tsx — The Upload Page

A drag-and-drop video uploader at /upload. Client component.

app/upload/page.tsxClient Component

How an upload works in the browser:

  • Pick a file — click the dashed dropzone or drag a file onto it. pick() validates it's a video (video/* or .mp4/.webm/.mkv/.mov/.avi/.m4v) and pre-fills the title from the filename.
  • Form fields — Title + Description (optional). No credentials are sent — the server resolves them itself.
  • Submit via XMLHttpRequest — uses XMLHttpRequest instead of fetch() for one reason: fetch can't track upload progress, but xhr.upload.onprogress can. The progress bar scales to 0–90% (the last 10% is the server-side FTP step which the browser can't see).
  • Stages — idle → uploading → storing → (error). "uploading" = browser→server; "storing" = server→StreamTape FTP (already done by the time the response arrives).
  • On success — saves the returned video to localStorage (upsertStoredVideo) and redirects to /watch/<streamtape_id>.
Why not fetch? fetch() has no upload-progress event. XMLHttpRequest.upload.onprogress gives real loaded/total bytes so we can draw a progress bar.

10 app/watch/[id]/page.tsx — The Watch Page

The video player page at /watch/<id>. The [id] is the StreamTape file id. Client component.

app/watch/[id]/page.tsxDynamic Route
  • Get the id — useParams() reads the id from the URL.
  • Resolve the video — fetches the remote library, falls back to localStorage, then finds the matching video by id. Also sets document.title to "<title> · Johanka" and resets it on unmount.
  • Loading state — a spinner while resolving.
  • 404 state — if the video isn't found, a "404 — this page doesn't exist" card.
  • Layout — a two-column grid: the <Player> + title + description + metadata (duration, size, upload time) + <WatchActions> on the left; a sidebar of up to 4 related videos (<VideoCard>) on the right (hidden on mobile, where they move below).

11 app/settings/page.tsx — The Operator Dashboard

A locked config page at /settings where you set StreamTape credentials, the folder id, a PostgreSQL DSN, and rotate the admin key. Client component.

app/settings/page.tsxClient Component · Locked

The page runs through a phase state machine: loading → (setup | lock | unlocked).

  • loading — calls GET /api/settings to discover the current state.
  • setup — no admin key exists yet. Shows a "create the key" form (two fields, must match, min 16 chars). POSTs {admin_key}.
  • lock — a key exists but you haven't entered it. Shows an unlock prompt. On submit, stores the key in-memory (setAdminKey) and reloads.
  • unlocked — shows the full dashboard: StreamTape login/password (password is masked — "set" indicator only), folder id, PostgreSQL DSN, an optional new admin key, a "Save" button, a live "Health" pill (calls /api/streamtape/health), and a "Run diagnostics" button (calls /api/streamtape/diagnose).
Security model: the admin key is held only in memory for the current tab (lib/admin-auth.ts) and sent as Authorization: Bearer <key> on every admin request. Reloading /settings re-prompts. The key is verified server-side against a SHA-256 hash (DB) or the env var.

14 POST /api/upload — The Upload Endpoint

This is the most complex route. It receives a multipart video upload and forwards it to StreamTape over FTP — without ever loading the whole file into memory.

app/api/upload/route.tsRoute Handler

The full pipeline:

  1. Create a temp dir — os.tmpdir()/johanka-<id>.
  2. Parse the multipart body as a stream — instead of await req.formData() (which buffers everything in RAM and OOMs on big files), it uses a custom parseMultipartStream() that streams the file part straight to a temp file on disk. Small text fields (title/description) stay in memory.
  3. Resolve credentials server-side — loadEffectiveSettings() (env wins over DB). Returns 400 if StreamTape isn't configured.
  4. Sanitize the title — clampUsername() strips odd characters and caps at 60 chars; falls back to the filename without extension.
  5. FTP upload — uploadViaFtp(creds, tempPath, safeName, folderId) streams the temp file to ftp.streamtape.com. Returns a StreamTape file id.
  6. Build the embed URL — embedUrl(fileid) → https://streamtape.com/e/<fileid>.
  7. Get the thumbnail — getThumbnailUrl(creds, fileid) hits /file/getsplash. May be null while StreamTape is still processing — the library re-resolves it later.
  8. Return the video object — as JSON with status 201. The client saves it to localStorage and redirects to /watch/<streamtape_id>.
  9. Cleanup — the finally block deletes the temp files no matter what.
Memory safety: the whole point of the custom multipart parser is that a 2GB video never holds more than a few KB of server RAM. The bytes go: browser → disk temp file → FTP. Without this, the old req.formData() approach OOM-killed the process at ~150MB on Render's free tier.

15 GET/POST /api/settings — The Config Endpoint

app/api/settings/route.tsRoute Handler · Locked

Stores operator config in the PostgreSQL settings table, protected by the admin key. Two verbs:

GET — read the current state

  • If a key is configured and you don't provide a valid one → 401 {locked:true}.
  • If a key is configured and yours is valid → returns the settings (env-overlaid).
  • If no key exists yet → 200 {needsSetup:true} (only key creation allowed).

POST — write

  • First run (no key): only {admin_key} is accepted. Must be ≥16 chars. Stored as SHA-256. Requires a DSN.
  • After that: requires a valid key. Saves StreamTape login/key/folder-id/DSN. Secrets are only replaced when a new value is sent (blank = keep). Can optionally rotate the admin key.

The DSN (PostgreSQL connection string) resolves as: env DATABASE_URL/POSTGRES_URL first, then the body field, then the ?postgres= query param. Env vars always win at overlay time via overlayEnv().

16 GET /api/streamtape/files — List the Library

app/api/streamtape/files/route.tsPublic · Cached

The home page's data source. Public (no admin key) because the browser calls it on load.

  • Resolves credentials server-side; returns {configured:false} if none.
  • Checks the 30s in-memory cache; returns {cached:true} on a hit.
  • On a miss: calls listFiles(creds, folderId) (paginates /file/listfolder), then resolveThumbnails() — resolves each file's splash URL with a concurrency cap of 5 (cached 10min/2min).
  • Maps raw StreamTape files into Video[] objects (pretty title via stripExt + replacing _- with spaces).
  • Caches and returns. On error → 502 with the message.

17 GET /api/streamtape/health — Validate Credentials

app/api/streamtape/health/route.tsAdmin Only

Admin-only. Resolves creds server-side and calls getAccountInfo() (StreamTape /account/info). Returns {configured, account, error}. Used by the settings page to show the live "Live / Attention / Not configured" pill. If StreamTape rejects the creds, returns a friendly "credentials were rejected" message instead of a stack trace.

18 GET /api/streamtape/diagnose — Connectivity Diagnostics

app/api/streamtape/diagnose/route.tsAdmin Only

Admin-only. A debugging tool for when "fetch failed" shows up. Runs three checks and returns a structured report:

  • DNS — dns.lookup('api.streamtape.com'); reports resolved IPs or the error.
  • API call — tries getAccountInfo(); reports ok/account or the error.
  • Proxy — checks HTTPS_PROXY env (masked password).

A suggest() function turns the results into plain-English advice (e.g. "DNS failed — try 1.1.1.1", "set HTTPS_PROXY", "check your API/FTP password").

21 Auth Routes — Sign-in, Session, Guest

Five small endpoints that power the optional Google sign-in + guest mode.

app/api/auth/config/route.tsPublic

GET — exposes the client-side Firebase config (API key, auth domain, project id) from runtime env. This works on Render/Docker where NEXT_PUBLIC_* can't be baked in at build time. These values are public anyway (they ship to the browser).

app/api/auth/logout/route.tsPublic

POST — clears both the session and guest cookies.

22 lib/streamtape.ts — The StreamTape API Client

A thin wrapper around the StreamTape REST API at https://api.streamtape.com. Every function takes an explicit StreamtapeCreds argument (login + key) so the server stays stateless.

lib/streamtape.tsServer Module

Notable pieces:

  • stFetch() — a shared fetch wrapper that adds a real User-Agent (Cloudflare blocks bare "undici"), a 20s timeout, optional HTTPS proxy support (via undici.ProxyAgent), and translateFetchError() which turns Node's opaque "fetch failed" into a helpful message (DNS failed / refused / reset / timeout / TLS).
  • request() — builds the URL, adds login+key auth params, calls stFetch, parses JSON, throws StreamTapeError if status !== 200.
  • listFiles(creds, folderId?) — paginates /file/listfolder (20 pages × 100 = 2000 file cap). Maps each entry to {fileid, name, size, created} (note: the file id is the linkid field). Returns newest-first.
  • embedUrl(fileid) — returns https://streamtape.com/e/<fileid> (the iframe player URL).
  • getThumbnailUrl(creds, fileid) — hits /file/getsplash. Returns the auto-generated poster URL (e.g. thumb.tapecontent.net/...) or null while still processing / on failure.
  • getDirectLink() — the two-step ticket flow (/file/dlticket then /file/dl) for a temporary direct mp4 link. Returns null on captcha files.
  • getFileInfo(), deleteFile(), getAccountInfo(), uploadFile() — thinner wrappers for the corresponding endpoints.
Why FTP instead of the HTTP upload? uploadFile() (StreamTape's /file/uploadfile) is capped at ~1MB by Cloudflare. Real videos are bigger, so uploads go over FTP instead (see lib/ftp.ts).

23 lib/ftp.ts — The FTP Uploader

lib/ftp.tsServer Module

Uploads video files to StreamTape over FTP using the basic-ftp library, because the HTTP API caps body size at ~1MB. Flow:

  1. connect() — connects to ftp.streamtape.com:21 with the user's API/FTP creds. Tries explicit FTPS (TLS upgrade) first, falls back to plain FTP if TLS is refused/blocked.
  2. uploadViaFtp() — prefixes the filename with a random 6-char token (so a duplicate name doesn't confuse the lookup), optionally cds into the configured folder, then streams the temp file to the server with client.uploadFrom(stream, remoteName). Memory stays flat because it reads from disk.
  3. resolveFileId() — StreamTape doesn't return a file id from the FTP transfer, so this polls /file/listfolder up to 3 times (1.5s apart) and matches by the normalized filename (spaces→underscores). Takes the most recent match. Returns null if it can't resolve (non-fatal — the embed link is built defensively).

The whole thing is wrapped in FtpError with a 502 status so the route can surface a clean message.

24 lib/multipart.ts — Memory-Safe Multipart Parser

lib/multipart.tsServer Module

A custom, dependency-free multipart/form-data stream parser. This is the key to handling large uploads without OOM.

  • Next's await req.formData() buffers the entire body in memory (and File.arrayBuffer() makes a second copy) — a 250MB video eats ~500–750MB RAM.
  • This parser instead consumes the body as a stream: small text fields are buffered in memory; the (huge) file part is written straight to a temp file on disk as bytes arrive. Peak memory is bounded by a few KB of lookahead.
  • Exports boundaryFrom() (extract the boundary token), parseMultipartStream() (the parser), and types ParsedUpload / MultipartFilePart.
  • The parser is a state machine (headers → body → suffix) that keeps a trailing window (keep) in case a delimiter is split across chunks, and waits for all file WriteStreams to finish before resolving.

25 lib/db.ts — The PostgreSQL Layer

lib/db.tsServer Module · Optional

Everything here is optional — if no DATABASE_URL is set, none of it runs and the app falls back to env vars. Uses the pg driver with a cached Pool per connection string (max 3 connections).

Two tables, auto-created on first use:

  • settings — a single-row table (id BOOLEAN PRIMARY KEY DEFAULT TRUE + a CHECK (id = TRUE) constraint enforces exactly one row). Columns: streamtape_login, streamtape_key, streamtape_folder_id, postgres_connection_string, admin_key_sha, updated_at. Additive migrations (ADD COLUMN IF NOT EXISTS) keep old databases working.
  • users — Google sign-in rows keyed by the Firebase uid. Columns: uid, email, display_name, photo_url, provider, created_at, last_login_at, updated_at.

Functions: loadSettingsFromDb, saveSettingsToDb (upsert with ON CONFLICT), getAdminKeySha / setAdminKeySha, upsertUser, getUserByUid.

Video metadata is NOT in the DB — the library always comes live from StreamTape. PostgreSQL only holds operator config + signed-in users.

26 lib/settings.ts & lib/server-settings.ts

lib/settings.tsServer Module

A tiny pure function resolveSettings(client?) that merges env vars over client-supplied values. pick(env, fallback) returns the env value if non-empty, else the fallback. Used by the data routes to get effective settings (env wins).

lib/server-settings.tsServer Module

The higher-level server helper used by every API route:

  • envDsn() — returns DATABASE_URL or POSTGRES_URL.
  • loadEffectiveSettings(dsn?) — loads settings from PostgreSQL (best-effort) then overlays env vars. This is what every route calls.
  • overlayEnv(db) — the inverse for the /settings response (returns snake_case settings with env overlaid).
  • Admin key — sha256Hex(), hashEqual() (timing-safe compare to prevent timing attacks), envAdminKey(), adminKeyConfigured(), adminTokenValid() (compares the SHA of the provided token to the stored hash), storeAdminKey(), adminTokenFromRequest() (reads Authorization: Bearer or ?key=), isAdminRequest().
Security note: the admin key is compared using timingSafeEqual on the SHA-256 hashes, which prevents timing-attack-based key guessing. The env var (JOHANKA_ADMIN_KEY) always wins over the DB hash.

37 Running & Deployment

37.1 Run locally (dev)

# Requirements: Node 20+
npm install

# StreamTape creds — free account at streamtape.com → Account → API/FTP
export STREAMTAPE_LOGIN=your_api_ftp_username
export STREAMTAPE_KEY=your_api_ftp_password
# Optional: one folder only (id from streamtape.com/f/<folder-id>/…)
export STREAMTAPE_FOLDER_ID=

npm run dev        # → http://localhost:3000  (upload at /upload)

37.2 Production build

npm run build && npm start
# npm start runs: node .next/standalone/server.js

37.3 Docker

# Build with the host's git version stamped into the image
APP_VERSION="$(git describe --tags --always)" docker compose up --build -d

The Dockerfile is a two-stage build:

  • Builder — installs build tools, runs npm ci, then npm run build. APP_VERSION is passed as a build arg (since .git is excluded from the image, git version resolution can't run inside).
  • Runner — copies .next/standalone + .next/static + public. Installs only wget (for the healthcheck) — no ffmpeg, keeping the image small. Runs node server.js on port 3000.

docker-compose.yml maps port 3000, passes all env vars (STREAMTAPE_*, DATABASE_URL, FIREBASE_*), and adds a wget-based healthcheck. scripts/standalone-copy.mjs is the postbuild step that copies static+public into .next/standalone so the standalone server is fully self-contained.

Recommended production setup: set STREAMTAPE_LOGIN/STREAMTAPE_KEY and optionally JOHANKA_ADMIN_KEY and DATABASE_URL as env vars (they always win and survive a fresh DB). Use the /settings UI only if you're storing them in PostgreSQL.

Quick definitions of every term you'll bump into while reading this project.
